# ADR 0009 — Free hosted AI and attendance-based speakers

Phase 9 adds free hosted transcription and analysis while retaining the existing processing steps and pipeline versions. Groq transcribes speech; Gemini supplies structured extraction. AssemblyAI and Anthropic remain explicit, optional adapters. Fake providers remain the keyless local/CI default and never send content externally. No Phase 10 features are included.

## Provider verification (25 November 2026)

Official [Groq speech documentation](https://console.groq.com/docs/speech-to-text) lists `whisper-large-v3-turbo` and `whisper-large-v3`, a **25 MB free upload limit**, word/segment timestamps with `verbose_json`, 16 kHz mono preprocessing, a 224-token context prompt, and a 10-second minimum billing duration. We default to Turbo, send compressed AAC/M4A directly, cap each file below 24,000,000 bytes, and bound hints to 224 UTF-8 bytes (a conservative token upper bound).

The [Groq free limits table](https://console.groq.com/docs/rate-limits) currently lists both Whisper variants at **20 RPM, 2,000 RPD, 7,200 audio seconds/hour and 28,800/day**. The default free alternative, `openai/gpt-oss-20b`, is listed at **30 RPM, 1,000 RPD, 8,000 TPM and 200,000 TPD**. Exact account quotas can differ. Retry-After is honored; account-wide consumption outside this application can still cause 429s.

**Deviation from the proposed Groq Llama default:** the current [model catalog](https://console.groq.com/docs/models) lists Llama 3.1/3.3 as enterprise-only, not as free-tier models. Automatically choosing them would contradict the zero-cost constraint. `GROQ_LLM_MODEL` therefore defaults to the listed free GPT-OSS model. The Groq adapter also supports JSON-object output for explicitly configured models without JSON-schema support. [Groq structured-output documentation](https://console.groq.com/docs/structured-outputs) lists strict schema support for GPT-OSS 20B/120B. No paid model is selected automatically.

Gemini defaults to **`gemini-3.5-flash-lite`**: its [model page](https://aistudio.google.com/docs/models/gemini-3.5-flash-lite) lists 1,048,576 input and 65,536 output tokens. The [pricing page](https://aistudio.google.com/docs/pricing#gemini-3.5-flash-lite) lists free input/output tokens and states that free-tier content can be used to improve Google's products. No tools, grounding, caching or other paid API features are requested. We cap generated output at 2,048 tokens and apply much smaller input budgets.

**Quota verification limitation:** [Gemini's rate-limit documentation](https://aistudio.google.com/docs/rate-limits) directs developers to their project's AI Studio limits; it does not publish a universal current free RPM/TPM/RPD allowance for this model. Consequently **1 RPM, 20 RPD and 32,000 TPM are conservative application defaults, not verified provider entitlements**. Operators must lower them to match their account if needed. Gemini quotas are per project and daily quotas reset at midnight Pacific; our rolling 24-hour cap is stricter. A key does not prove free-tier eligibility: use free-tier projects/accounts with billing disabled. The application cannot inspect or change account billing.

## Speech and speaker provenance

`transcription.per_track_speakers` is off by default. When enabled for a live mixed-audio source, transcription waits for participant exports to finalize, then reads each uploaded track through a workspace-scoped attendance join. Speaker records retain the attendance person's ID, authenticated user's ID and display name. Track offsets are added to restored original timestamps. Uploaded recordings and mixed fallback use the generic label “Speaker”; no diarization labels are published.

ffmpeg decodes local scratch audio to mono 16 kHz PCM. RMS is measured in 20 ms frames; frames above -40 dB receive 150 ms padding and neighboring intervals merge. This is energy-based silence detection, not a neural voice detector. ffmpeg trims the retained sample ranges and concatenates them into AAC chunks. The retained-range map translates chunk/trimmed timestamps back to the original track. Chunks are at most five minutes (smaller when the configured quota requires it), overlap by up to one second, and contain at most 100 ranges to bound command size. Duplicate overlap words are dropped.

Tracks with no detected speech are skipped. Near-identical overlapping text is compared across tracks and the louder RMS window wins. Different overlapping text remains. Echo cancellation is heuristic: background noise can count as speech, quiet speech can be lost, repeated simultaneous words can be mistaken for bleed, and acoustic echo may remain. Speakers identify the account owning a microphone, not every physical person near it. Shared microphones, clock offsets, dropped packets and model timestamp errors limit attribution quality. Fake-provider fixtures do not evaluate acoustic accuracy.

Before any track submission, the worker estimates padded speech and per-chunk billing overhead against configured hour/day limits and shared remaining capacity. If multi-track capture would exceed them, it durably chooses mixed audio, records `free_quota_speaker_fallback`, and displays “Fallback: no speaker labels.” Missing/failed participant audio also selects mixed fallback. A silent meeting can complete without an external request.

Each successful chunk is checkpointed in Postgres, scoped to the processing run, meeting and workspace. Raw text stays in content tables, never in job payloads or progress metadata. Resumed jobs reuse chunks rather than repeating successful uploads. Checkpoints cascade on purge. Source plans are persisted so changing available quota cannot switch source midway through a run.

## Quota recovery and extraction

All workers and `check:live` share Redis quota reservations keyed by a hash of the provider credential. Atomic weighted rolling token buckets check every applicable budget before charging any; tokens return when reservations expire. This is deliberately stricter than continuously refilling buckets, preventing day-boundary bursts. Request counts, estimated tokens, audio seconds, overlap and minimum audio billing are included. Redis failure defers work instead of bypassing quotas. All workers sharing an account should use the same configured key and Redis.

429s become durable `waiting_external` states with an estimated retry time. Hour/day exhaustion gets a long wait when no Retry-After is supplied. Quota waits do not exhaust ordinary failure attempts, and resume starts a fresh execution deadline. The driver checks the saved retry time even if Redis jobs disappear and the sweeper recreates them. Transient 5xx errors honor Retry-After and keep bounded normal retry attempts. Authentication failures, rejected audio and oversized prepared files are permanent, content-free errors. Prepared audio remains playable when an external step fails.

Gemini and Groq analysis reuse the extraction schema, prompt-injection delimiters, original segment citation guard, validation-error retry and map/reduce helpers. Request budgets use a conservative UTF-8 byte upper bound and reserve maximum output tokens. Uncited or invalidly cited items are dropped. After one model repair attempt, structurally valid items may be salvaged without inventing evidence; corrected extraction and citation filtering mark the document/items low confidence. A configured `LLM_FALLBACK_PROVIDER` is used only for quota exhaustion and may only be Gemini or Groq. Paid adapters are never automatic fallbacks.

## Privacy

`workspace_settings.external_ai_enabled` defaults to false. Existing owner/admin workspace-update authorization controls it; a separate content-free audit action records toggles. The API exposes provider names without keys. Settings, room consent and upload forms disclose the active third parties. Real adapters are blocked before transcription/analysis and checked again immediately before external requests, including fallback and resumed chunks. Disabling affects future requests; it cannot recall an already submitted request. Local fake fixtures are exempt because they send no data externally.

Provider keys, signed audio URLs, prompts, transcript text, summary text and upstream error bodies must not enter logs, errors, audit metadata or queue payloads. HTTP adapters sanitize network and provider failures. Identity deletion nulls only optional identity columns in composite foreign keys, preserving tenant/revision scope; preserve the selective SET NULL clauses in migrations 0007 and 0008 after regeneration.

## Live checks

`pnpm check:live <local-audio-file>` uses real configured Groq transcription and Gemini/Groq analysis, ffmpeg and shared Redis limits, without accessing the database. Calling it authorizes sending that file to the disclosed providers. It reports duration, word count, speaker count, item count, retained citation validity and runtime. `--show` explicitly prints transcript/document content. A single file has one generic speaker because it supplies no attendance provenance. Real two-person speaker attribution must be checked through an opted-in live workspace with the per-track flag on.

The script is never part of CI. CI uses mocked HTTP for real adapters and fake providers for browser flows. A passing fake-provider call verifies attendance wiring, not hosted-model quality. Actual real-key checks and microphone quality must be reported separately; do not claim them merely because mocked or fake-device tests pass.
